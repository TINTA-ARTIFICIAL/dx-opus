# DECISION LOG ENTRY: DL_20260508_SYSTEM_038

## DECISION

Introducir el componente **EDITOR DIGITAL** como mecanismo central de orquestación del flujo en D-X-OPUS. El Editor Digital combina un artefacto de estado persistente (`WORKFLOW_STATE.md`) con un prompt de entrada de sesión (`PROMPT_SESSION_ORCHESTRATOR`) que actúa como editor literario clásico — acompañando al escritor desde el inicio del proyecto hasta la entrega final.

## RATIONALE

El test E2E TC-3.1 (TA_Bottom_Up) reveló que los prompts actuales no tienen mecanismo alguno que obligue a respetar el flujo definido. El LLM toma decisiones de flujo por su cuenta y tiende a acelerar hacia el output final (escritura) saltándose pasos críticos como la fase de anotación, la validación de research, o el debate de ideas.

Dos problemas distintos requieren solución conjunta:

1. **Orquestación:** el sistema no tiene memoria de flujo entre sesiones ni mecanismo para verificar prerequisites antes de avanzar
2. **Comunicación:** el editor no sabe en qué punto del proceso está, qué ha completado, qué viene después ni qué decisiones ha tomado previamente

La metáfora del **editor literario clásico** (editor de editorial que asiste al escritor en ideación, creación y corrección) define el tono y el rol del componente: no es un gestor técnico de estados sino un colaborador editorial que conoce el proceso, respeta la autonomía del escritor y advierte antes de tomar atajos.

## ARCHITECTURE DECISION

**Opción seleccionada: D — Híbrido WORKFLOW_STATE + SESSION_ORCHESTRATOR**

Descartadas:
- Opción A (soft enforcement en prompts): depende del LLM respetando instrucciones — demostrado que falla
- Opción B (WORKFLOW_STATE solo): sin orquestador activo el editor sigue sin guía al inicio de sesión
- Opción C (SESSION_ORCHESTRATOR solo): sin estado persistente no hay continuidad entre sesiones

## COMPONENTS

### Componente 1: WORKFLOW_STATE.md

Artefacto persistente que vive en `config/` del proyecto. Se actualiza al final de cada sesión significativa.

**Contenido:**
- Fase actual del proyecto (Discovery, Research, Writing, Evaluation)
- Pasos completados con fecha y artefactos producidos
- Decisiones editoriales tomadas (saltos autorizados, retrocesos, opciones elegidas)
- Próximo paso recomendado
- Notas del Editor Digital para la próxima sesión

**Ciclo de vida:**
- Creado por `PROMPT_PROJECT_DISCOVERY` al cerrar la primera sesión
- Actualizado por `PROMPT_SESSION_ORCHESTRATOR` al final de cada sesión
- Cargado en Project Knowledge al inicio de cada sesión

### Componente 2: PROMPT_SESSION_ORCHESTRATOR

Prompt de entrada que se ejecuta al inicio de cada sesión. Actúa como editor literario digital.

**Comportamiento:**
1. Lee `WORKFLOW_STATE.md` y reconstruye el contexto del proyecto
2. Saluda al escritor con un resumen conversacional de dónde están
3. Presenta el siguiente paso recomendado con justificación editorial
4. Ofrece opciones: continuar, saltar (con advertencia), volver atrás, explorar
5. Verifica prerequisites antes de cualquier avance
6. Si prerequisites no se cumplen: explica qué falta y por qué importa
7. Si el editor quiere saltar: advierte consecuencias y pide confirmación explícita
8. Al final de la sesión: actualiza WORKFLOW_STATE y deja nota para próxima sesión

**Tono:** editor literario clásico — colaborador, conocedor del proceso, respetuoso de la autonomía del escritor, directo cuando algo puede comprometer la calidad del output.

**NO es:** un gestor técnico, un chatbot de soporte, un validador burocrático.

## INTEGRATION WITH EXISTING PROMPTS

Todos los prompts existentes deben añadir:
- Bloque `PREREQUISITE_CHECK` al inicio: lista de artefactos y condiciones requeridas
- Bloque `SESSION_CLOSE` al final: instrucciones para actualizar WORKFLOW_STATE
- Declaración explícita de `NEXT_STEP` al completar el prompt

El SESSION_ORCHESTRATOR no reemplaza los prompts existentes — los orquesta.

## EDITOR DIGITAL ROLE DEFINITION

El Editor Digital participa en todas las fases del proyecto:

| Fase | Rol del Editor Digital |
|---|---|
| Discovery | Escucha la visión del escritor, evalúa el material, propone el plan inicial |
| Research | Verifica que la investigación es suficiente antes de escribir, gestiona la fase de anotación |
| Writing | Mantiene coherencia con el plan, advierte cuando el texto se desvía de la intención |
| Evaluation | Plantea las preguntas difíciles sobre calidad antes de dar por cerrado el trabajo |
| Entre sesiones | Recuerda, orienta, retoma — como si nunca hubiera habido interrupción |

## OPEN QUESTIONS

1. ~~¿El SESSION_ORCHESTRATOR debe ser el único punto de entrada a cada sesión, o puede el editor invocar prompts directamente saltándose el orquestador?~~ **RESUELTO: OBLIGATORIO.** El SESSION_ORCHESTRATOR es el único punto de entrada a cada sesión. El editor no puede invocar prompts directamente saltándose el orquestador. Si el editor quiere ejecutar un prompt específico, lo solicita al SESSION_ORCHESTRATOR que verifica prerequisites y gestiona la transición. Revisable en sprints posteriores si genera fricción.
2. ~~¿WORKFLOW_STATE se actualiza automáticamente (auto-save) o el editor lo sube manualmente al Project Knowledge?~~ **RESUELTO: AUTO-SAVE.** WORKFLOW_STATE.md se actualiza automáticamente mediante el mecanismo de auto-save genérico (ARQUITECTURA_AUTO_SAVE_GENERICA). El editor no necesita gestionar este archivo manualmente.
3. ~~¿El Editor Digital tiene un nombre/persona definido, o es simplemente "el sistema"?~~ **RESUELTO: EDITORIAL_PROFILE.** El Editor Digital no tiene nombre propio sino que adopta el perfil de la editorial o publicación destino del proyecto (EDITORIAL_PROFILE). El EDITOR_PROFILE define cómo escribe el escritor; el EDITORIAL_PROFILE define cómo edita el Editor Digital — su criterio, sus estándares, su tono editorial. Cada proyecto puede tener un Editor Digital diferente según la publicación destino. El EDITORIAL_PROFILE deberá extenderse para incluir comportamiento editorial activo (no solo referencia de estilo).
