# DECISION LOG ENTRY: DL_20260509_SYSTEM_039

## DECISION

Crear carpeta `D-X-OPUS/workflows/` como ubicación dedicada para los documentos de orquestación del flujo en el entorno instalado del editor. Los workflows dejan de estar dispersos o ausentes y pasan a tener una ubicación canónica propia separada de `resources/`.

## RATIONALE

El test E2E TC-3.1 reveló que los workflows (WORKFLOW_RESEARCH, WORKFLOW_WRITING, WORKFLOW_ACTIVATION) no están incluidos en el package instalado. Sin workflows en Project Knowledge el LLM no tiene referencia de la secuencia correcta de pasos y toma decisiones de flujo autónomas — causa raíz de la mayoría de bugs de flujo observados en el test.

La carpeta `resources/` no es el lugar correcto para los workflows porque mezclaría dos tipos distintos de artefactos: configuración técnica (SAH, CVC, AUTO_SAVE_CONFIG) con documentos de orquestación de proceso. Una carpeta dedicada `workflows/` es más limpia, escalable y anticipa el SESSION_ORCHESTRATOR (DL_038) que necesitará leerlos sistemáticamente.

## STRUCTURE

```
D-X-OPUS/
├── prompts/       ← prompts ejecutables (PROMPT_*.md)
├── templates/     ← templates de generación (TEMPLATE_*.md)
├── resources/     ← config técnica (SAH, CVC, AUTO_SAVE_CONFIG)
├── workflows/     ← NEW: documentos de orquestación de flujo
├── tools/         ← scripts de automatización
└── projects/      ← proyectos del editor
```
