# DECISION LOG ENTRY: DL_20260507_SYSTEM_037

## DECISION

Añadir flag `--patch N` a `create-release-package.sh` (v1.1 → v1.2) para soportar generación de versiones hotfix/patch (v1.X.Y donde Y > 0) sin edición manual del script.

## RATIONALE

Durante el primer test E2E del hotfix v1.4.1 se descubrió que el script solo generaba versiones `.0` (v1.4.0, v1.5.0...) con el número de patch hardcodeado. Para publicar el hotfix v1.4.1 había que editar manualmente la línea `VERSION="v1.${SPRINT_NUM}.0"`, lo cual es error-prone y no escalable. El fix correcto es parametrizar el patch via flag CLI.

## CHANGES

| Campo | Antes (v1.1) | Después (v1.2) |
|---|---|---|
| VERSION calculation | `v1.${SPRINT_NUM}.0` (hardcoded) | `v1.${SPRINT_NUM}.${PATCH_NUM}` |
| PATCH_NUM default | — | `0` (sprint release normal) |
| Nuevo flag | — | `--patch N` |
| Usage | sin soporte patch | `./create-release-package.sh sprint-4 --patch 1` |

## USAGE EXAMPLES

```bash
# Sprint release normal (v1.5.0)
./tools/create-release-package.sh sprint-5

# Hotfix release (v1.4.1)
./tools/create-release-package.sh sprint-4 --patch 1

# Segunda corrección (v1.4.2)
./tools/create-release-package.sh sprint-4 --patch 2
```
