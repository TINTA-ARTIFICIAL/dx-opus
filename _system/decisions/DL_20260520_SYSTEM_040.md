# DECISION LOG ENTRY: DL_20260520_SYSTEM_040

## DECISION

Automatizar la generación de artefactos de desarrollo (DLs, READMEs, mensajes de commit) en los chats de desarrollo mediante tres niveles de implementación progresiva: (1) Project Instructions con protocolo de cierre obligatorio — inmediato; (2) PROMPT_DEV_CLOSURE como prompt especializado — Sprint 5; (3) Dev Agent automatizado — Fase 2.

## RATIONALE

El test E2E TC-3.1 demostró que la generación de DLs, actualización de READMEs y otros artefactos de mantenimiento del repositorio dependen completamente de que el desarrollador los solicite manualmente. Esto genera inconsistencias, omisiones y pérdida de trazabilidad. En esta sesión se generaron 4 DLs y múltiples READMEs que en ningún caso fueron iniciativa del LLM — siempre del desarrollador.

El problema es estructural: los chats de desarrollo no tienen instrucciones que les indiquen cuándo y cómo generar estos artefactos de forma proactiva.

## ARCHITECTURE

### Nivel 1 — Project Instructions (inmediato, Sprint 5)

Añadir a las Project Instructions de cada chat de desarrollo un protocolo de cierre obligatorio:

```
PROTOCOLO DE CIERRE DE SESIÓN DE DESARROLLO

Al detectar que en la sesión se ha producido cualquiera de estos eventos:
- Decisión arquitectónica tomada
- Artefacto nuevo creado o modificado
- Bug identificado y resuelto
- Cambio de interfaz entre subsistemas
- Modificación de proceso o herramienta

Ejecutar automáticamente sin esperar solicitud del desarrollador:

1. GENERAR DL — con el número siguiente al último registrado en decisions/README.md
2. ACTUALIZAR README del directorio afectado
3. ACTUALIZAR decisions/README.md — contadores y tabla de recent decisions
4. LISTAR archivos para subir al repo con destinos exactos
5. GENERAR mensaje de commit estandarizado
6. VERIFICAR si MASTER_PLAN necesita actualización

Si hay duda sobre si algo merece DL: preguntar al desarrollador.
Si la decisión es clara: generar directamente y presentar para validación.
```

### Nivel 2 — PROMPT_DEV_CLOSURE (Sprint 5)

Prompt especializado que el desarrollador puede invocar explícitamente al cerrar una sesión compleja. Orquesta el proceso completo:

1. Lee el historial de la sesión y detecta todos los eventos relevantes
2. Genera todos los DLs necesarios (puede ser más de uno por sesión)
3. Actualiza todos los READMEs afectados
4. Produce lista completa de archivos para subir al repo
5. Genera mensaje de commit con referencias a DL IDs
6. Evalúa si MASTER_PLAN necesita actualización y qué secciones

Ubicación: `_system/PROMPT_DEV_CLOSURE.md`
Invocación: escribir `PROMPT_DEV_CLOSURE` en cualquier chat de desarrollo

### Nivel 3 — Dev Agent (Fase 2)

Cuando se migre a arquitectura de agentes, un Dev Agent detecta cambios en el repositorio y ejecuta el protocolo de cierre automáticamente, sin intervención humana. Integrado con GitHub webhooks.
