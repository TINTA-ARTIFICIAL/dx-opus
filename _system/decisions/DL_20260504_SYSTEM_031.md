# DECISION LOG ENTRY: DL_20260504_SYSTEM_031

## DECISION

Se añaden TEMPLATE_PROJECT_README.md y TEMPLATE_PROJECT_INSTRUCTIONS.md como templates formales para auto-generación estandarizada de artefactos de proyecto.

## RATIONALE

**Gap identificada:** TOOL_CREATE_PROJECT generaba PROJECT_README.md y Project Instructions de forma ad-hoc, sin templates estandarizados.

**Problemas:**
- PROJECT_README generado con código hardcodeado
- Project Instructions hardcodeadas para Marco Laucelli específicamente
- No reutilizable para otros editores
- No mantenimiento centralizado de estructura
- No estandarización de contenido

**Solución:** Templates formales con variables dinámicas:

**TEMPLATE_PROJECT_README.md:**
- Variables: {PROJECT_CODE}, {PROJECT_NAME}, {EDITOR_PROFILE}, etc.
- Estructura estándar de estado de workflows
- Enlaces automáticos a Drive
- Guías de actualización manual
- Troubleshooting integrado

**TEMPLATE_PROJECT_INSTRUCTIONS.md:**
- Personalización automática según EDITOR_PROFILE activo
- Soporte para múltiples editores
- Session opener adaptativo
- Lógica condicional para detección de perfiles
- Generación automática por TOOL_CREATE_PROJECT

## AFFECTED SUBSYSTEMS

- **SYSTEM:** Añade 2 templates formales al inventario de artefactos
- **TOOLS:** TOOL_CREATE_PROJECT debe usar templates en lugar de código hardcodeado

## ARTIFACTS AFFECTED

| Artifact | Action | Notes |
|----------|--------|-------|
| TEMPLATE_PROJECT_README.md | CREATE | Template con variables dinámicas |
| TEMPLATE_PROJECT_INSTRUCTIONS.md | CREATE | Template para Claude.ai project instructions |
| TOOL_CREATE_PROJECT.gs | MODIFY | Usar templates + función de generación automática |
| AUTO_SAVE_CONFIG.yaml | MODIFY | Documentar scope PROJECT vs EDITOR |

## IMPLEMENTATION PLAN

### Fase 1: Templates
1. Crear TEMPLATE_PROJECT_README con estructura completa
2. Crear TEMPLATE_PROJECT_INSTRUCTIONS con lógica condicional
3. Definir todas las variables de sustitución

### Fase 2: Integration  
1. Modificar TOOL_CREATE_PROJECT para usar templates
2. Función generateProjectInstructions() con personalización automática
3. Testing de generación para múltiples editores

### Fase 3: Validation
1. Crear proyecto de prueba con nuevo sistema
2. Verificar personalización correcta de instructions
3. Verificar estructura estándar de PROJECT_README

## INTEGRATION NOTES

Estos templates corresponden al NIVEL 2 (setup de proyecto) y complementan los templates del NIVEL 1 (TEMPLATE_EDITOR_CONFIG).

**Relación arquitectónica:**
- NIVEL 1: TEMPLATE_EDITOR_CONFIG (configuración del editor)
- NIVEL 2: TEMPLATE_PROJECT_README + TEMPLATE_PROJECT_INSTRUCTIONS (configuración del proyecto)

**Benefit:** Setup completamente automático y estandarizado para cualquier editor.
