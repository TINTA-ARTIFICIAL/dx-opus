# DECISION LOG ENTRY: DL_20260504_SYSTEM_032

## DECISION

Se añade PROMPT_PROJECT_DISCOVERY v1.0 como prompt de sistema para gestionar la primera sesión de cualquier proyecto D-X-OPUS. Produce PROJECT_NOTES que orienta las sesiones posteriores.

## RATIONALE

**Gap crítica identificada:** Sin PROMPT_PROJECT_DISCOVERY, la primera sesión de proyecto no tiene orientación automática.

**Problemas:**
- Editor llega con material (referencias, notas, ideas) sin saber qué workflow usar
- Session opener no tiene forma de bifurcar apropiadamente
- Material pre-workflow no tiene ubicación definida
- Primera sesión requiere intervención manual constante

**Solución:** PROMPT_PROJECT_DISCOVERY con Q&A adaptativo:
- Detecta material del editor y objetivo final
- Determina workflow apropiado (Research/Writing/Activation)
- Organiza material en carpeta `_discovery/`  
- Produce PROJECT_NOTES que documenta dirección del proyecto
- Auto-save integrado según ARQUITECTURA_AUTO_SAVE_GENERICA

**Función en arquitectura:**
- Se ejecuta automáticamente cuando NO existe PROJECT_NOTES
- Session opener depende de PROJECT_NOTES para bifurcación
- Convierte material ad-hoc en proyecto orientado

## AFFECTED SUBSYSTEMS

- **SYSTEM:** Añade nuevo prompt de sistema (no de workflow específico)
- **ALL WORKFLOWS:** Todos dependen de PROJECT_NOTES para orientación inicial
- **WRITING:** Session opener usa PROJECT_NOTES para bifurcación

## ARTIFACTS AFFECTED

| Artifact | Action | Notes |
|----------|--------|-------|
| PROMPT_PROJECT_DISCOVERY.md | CREATE v1.0 | Prompt completo con Q&A adaptativo |
| AUTO_SAVE_CONFIG.yaml | MODIFY | Añadir PROJECT_NOTES a artefactos SYSTEM |
| TEMPLATE_PROJECT_INSTRUCTIONS.md | MODIFY | Session opener debe invocar PROJECT_DISCOVERY si no hay PROJECT_NOTES |
| Estructura Drive proyectos | MODIFY | Añadir carpeta `_discovery/` para material pre-workflow |

## IMPLEMENTATION PLAN

1. Crear PROMPT_PROJECT_DISCOVERY con casos de uso completos
2. Integrar auto-save de PROJECT_NOTES 
3. Añadir `_discovery/` a estructura automática de proyectos
4. Actualizar session opener para detectar ausencia de PROJECT_NOTES
5. Testing con diferentes tipos de material inicial

## INTEGRATION NOTES

**Posición en arquitectura:**
- Subsistema: SYSTEM (no pertenece a workflow específico)
- Función: Determina QUÉ workflow activar
- Dependencia: Session opener lo invoca automáticamente cuando necesario

**Relación con estructura Drive:**
- `_discovery/` = material pre-workflow (organizado por PROJECT_DISCOVERY)
- `[workflow]/` = material procesado (organizado por prompts específicos)

**No es feature de R2 - es implementación faltante de R1:** El session opener bifurcado requiere PROJECT_NOTES para funcionar. Sin PROJECT_DISCOVERY, no hay forma de generar PROJECT_NOTES automáticamente.
