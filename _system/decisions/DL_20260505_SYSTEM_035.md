# DL_20260505_SYSTEM_035 — Automated Release Package System

## DECISION

Implementar sistema automatizado de release packages integrado en el flujo de cierre de sprint, para reemplazar la instalación manual de 60+ archivos individuales.

## CONTEXT

El setup de R1 requería descarga manual de 60+ archivos desde GitHub, tomando 45–60 minutos con alto riesgo de errores por copy/paste y posibles inconsistencias de versión entre archivos. Con el sistema operacional en múltiples editores, este friction point se convirtió en bloqueante para la adopción.

## SOLUTION ADOPTED

Sistema de tres componentes integrados en el sprint workflow:

### 1. `create-release-package.sh`
Script bash ejecutado al cierre de cada sprint:
- Detecta y copia automáticamente todos los artefactos del repo usando mappings declarativos
- Genera `PACKAGE_INFO.md` con inventario completo y metadatos del sprint
- Genera `MANIFEST.txt` con checksums SHA256
- Crea ZIP y publica GitHub release
- Flags `--dry-run` y `--no-release` para validación segura
- Compatible con bash 3.x (macOS)

### 2. `TOOL_SETUP_EDITOR_ENVIRONMENT.gs` v1.1
Setup tool con arquitectura primario/fallback:
- **Primary:** Descarga ZIP de GitHub releases, extrae con `Utilities.unzip()`, instala a Drive
- **Fallback:** Descarga individual archivo por archivo si el ZIP falla
- Detección de versión instalada con marcador `.dx-opus-version`
- Verificación post-install de archivos críticos
- Retry con backoff exponencial

### 3. Versioning sprint-aligned
```
vMAJOR.SPRINT.PATCH
v1.4.0 = Sprint 4 (primer release oficial)
v1.5.0 = Sprint 5
v2.0.0 = R2
```

## OUTCOME

- **Setup time:** 45–60 min → 5–10 min (reducción del 90%)
- **Errores:** Eliminados (instalación automatizada)
- **Consistencia:** Garantizada (todos los archivos del mismo commit)
- **Overhead sprint:** ~5 minutos adicionales al cierre

## TECHNICAL NOTES

**Issue encontrado y resuelto:** `declare -A` (arrays asociativos) requiere bash 4.0+. macOS incluye bash 3.2. Resuelto reemplazando con variables simples `COUNT_PROMPTS`, `COUNT_TEMPLATES`, etc.

**Issue encontrado y resuelto:** `extract_recent_changes.sh` referenciado en el template original no existía. Resuelto con `git log --oneline -10 --no-merges` inline.
