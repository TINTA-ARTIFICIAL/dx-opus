# D-X-OPUS System Templates

**Directory:** _system/templates/  
**Purpose:** Standardized templates for auto-generation of project artifacts  
**Updated:** May 2026 (R1 Implementation)  
**Status:** Active

---

## Overview

This directory contains formal templates that enable standardized, automated generation of key D-X-OPUS artifacts. These templates support multi-editor setups and ensure consistency across all projects and configurations.

**Key Innovation:** Templates use variable substitution to generate personalized artifacts automatically, eliminating manual configuration and ensuring standardization.

---

## Template Architecture

### Two-Tier Template System

#### **LEVEL 1 Templates (Editor Setup)**
**Scope:** Personal configuration of the editor  
**Frequency:** Created once during SETUP_INICIAL_D_X_OPUS  
**Persistence:** Lives in editor's personal configuration

#### **LEVEL 2 Templates (Project Setup)**  
**Scope:** Project-specific configuration and documentation  
**Frequency:** Generated for each new project  
**Persistence:** Lives within each project

---

## TEMPLATE_EDITOR_CONFIG.md

**Personal configuration template for editors.**

### Purpose
- Documents complete D-X-OPUS setup for an editor
- Tracks active projects automatically
- Maintains usage statistics and preferences
- Serves as troubleshooting reference

### Key Features
- **Auto-tracking:** Updated automatically when projects are created
- **Technical documentation:** Drive URLs, Apps Script configuration, Claude templates
- **Statistics:** Usage patterns, project count, activity metrics  
- **Personal notes:** Editor preferences and customizations

### Variable Substitution
```yaml
# During setup, manually filled:
editor_name: [Editor's full name]
drive_root_folder: [URL to D-X-OPUS Drive folder]
main_profile: [EDITOR_PROFILE filename]

# Auto-updated by system:
last_config_update: [Auto timestamp]
project_count: [Auto incremented]
last_project_created: [Auto date]
```

### Sections
1. **Personal Information** - Basic editor data
2. **Technical Configuration** - Drive, Apps Script, Claude setup
3. **Editorial Configuration** - EDITOR_PROFILE and WRITING_CONTEXTS
4. **Personal Library** - Content available for Activation
5. **Active Projects** - Auto-maintained list with status
6. **Usage Statistics** - Auto-tracked metrics
7. **Personal Notes** - Editor's preferences and observations

### Usage
```bash
# Created during editor setup
cp TEMPLATE_EDITOR_CONFIG.md _editor/config/EDITOR_CONFIG.md
# Then manually fill initial configuration
# System auto-updates thereafter
```

## TEMPLATE_PROJECT_README.md

**Project status and configuration documentation template.**

### Purpose
- Documents project configuration and current state
- Provides workflow status tracking table
- Contains links and troubleshooting information
- Serves as project dashboard for editors

### Key Features
- **Dynamic generation:** All project-specific variables auto-substituted
- **Status tracking:** Table for manual updates of workflow progress
- **Auto-links:** Direct Drive folder links generated automatically
- **Troubleshooting:** Project-specific diagnostic information

### Variable Substitution
```yaml
# Auto-substituted during project creation:
{PROJECT_CODE}          # e.g., "TA"
{PROJECT_NAME}          # e.g., "Bottom Up"
{EDITOR_PROFILE}        # e.g., "EDITOR_PROFILE_MARCO_LAUCELLI"
{START_DATE}            # e.g., "2026-05-04"
{SYSTEM_VERSION}        # e.g., "R1"
{DRIVE_URL}             # Auto-generated Drive folder URL
{PROJECT_NAME_CLEAN}    # Project name safe for folder naming
```

### Generated Sections
1. **Project Header** - Code, name, dates, editor
2. **Editor Environment** - Prompts and configuration status
3. **Workflow Status Table** - Manual tracking of progress
4. **Drive Structure** - Auto-generated folder organization
5. **Configuration** - Auto-save and naming patterns
6. **Statistics** - Auto-updated project metrics
7. **Next Steps** - Context-appropriate recommendations

### Usage
```javascript
// Generated automatically by TOOL_CREATE_PROJECT
const readme = generateProjectReadme(projectCode, projectName, editorProfile);
createProjectFile(projectFolder, "PROJECT_README.md", readme);
```

## TEMPLATE_PROJECT_INSTRUCTIONS.md

**Claude.ai project instructions template with personalization.**

### Purpose
- Generates personalized Claude.ai project instructions for each project
- Adapts to editor's EDITOR_PROFILE automatically
- Supports multi-editor scenarios with profile detection
- Provides consistent session opener behavior

### Key Features
- **Profile adaptation:** Instructions personalized to editor's style and preferences
- **Multi-editor support:** Handles projects with multiple collaborating editors
- **Conditional logic:** Different instructions based on available profiles
- **Session guidance:** Complete session opener with PROJECT_DISCOVERY integration

### Variable Substitution
```yaml
# Project identification:
{PROJECT_CODE}          # Short project code
{PROJECT_NAME}          # Full project name
{EDITOR_NAME}           # Primary editor name
{EDITOR_PROFILE_ID}     # EDITOR_PROFILE filename
{SYSTEM_VERSION}        # D-X-OPUS version

# Dynamic behavior:
{PROFILE_DETECTION_LOGIC}   # Single vs multiple profile logic
{EDITOR_CONTEXT}            # Editor-specific context information
```

### Conditional Templates

#### **Single Profile Mode**
```markdown
Revisa el knowledge de este proyecto y confirma que el EDITOR_PROFILE activo es:
{EDITOR_PROFILE_ID} ({EDITOR_NAME})

Si está correcto, confírmalo en una línea y continúa.
```

#### **Multiple Profile Mode**  
```markdown
Revisa el knowledge de este proyecto y localiza todos los archivos
EDITOR_PROFILE disponibles.

Lista los disponibles y pregunta cuál activar para esta sesión.
No continúes hasta tener el perfil activo confirmado.
```

### Generated Components
1. **Project Context** - Code, name, system version
2. **Session Opener** - 3-step process with auto-detection
3. **Profile Management** - Single or multi-editor logic
4. **Workflow Bifurcation** - PROJECT_DISCOVERY integration
5. **Permanent Rules** - Auto-save, tracking, behavior guidelines

### Usage
```javascript
// Generated automatically with profile-specific logic
const instructions = generateProjectInstructions(projectCode, projectName, editorProfile);
// Included in PROMPTS_PACKAGE for Claude.ai setup
```

## Template Development

### Creating New Templates

#### **Standard Format**
```markdown
---
id:          TEMPLATE_[NAME]
type:        TEMPLATE
subsystem:   SYSTEM
version:     1.0
status:      ACTIVE
created:     YYYY-MM-DD
updated:     YYYY-MM-DD
owner_chat:  system-architecture
---

[Standard headers with CHANGELOG, DEPENDENCIES, DESCRIPTION]

# TEMPLATE: [NAME]
[Template content with variables]
```

#### **Variable Patterns**
- **Project:** `{PROJECT_CODE}`, `{PROJECT_NAME}`
- **Editor:** `{EDITOR_NAME}`, `{EDITOR_PROFILE}`
- **System:** `{SYSTEM_VERSION}`, `{START_DATE}`
- **Dynamic:** `{DRIVE_URL}`, `{PROJECT_NAME_CLEAN}`

#### **Documentation Requirements**
1. **Purpose** - Clear explanation of template function
2. **Variables** - Complete list with examples
3. **Usage** - How and when template is applied
4. **Output** - What the generated artifact looks like

### Modification Guidelines

#### **Before Modifying Templates**
1. **Create DL entry** documenting change rationale
2. **Test generation** with multiple project types
3. **Verify backward compatibility** with existing projects
4. **Update AUTO_SAVE_CONFIG** if new artifact types

#### **Variable Changes**
- **New variables:** Update generation functions in TOOL_CREATE_PROJECT
- **Removed variables:** Ensure generation doesn't fail
- **Changed patterns:** Update all dependent templates

#### **Testing New/Modified Templates**
1. **Manual generation test** with TOOL_CREATE_PROJECT
2. **Multi-editor test** with different EDITOR_PROFILEs
3. **Edge case test** with special characters in project names
4. **Integration test** with Claude.ai project setup

## Integration Points

### With Tools
- **TOOL_CREATE_PROJECT.gs:** Primary consumer of all templates
- **SETUP_INICIAL_D_X_OPUS.md:** Uses TEMPLATE_EDITOR_CONFIG process

### With System
- **AUTO_SAVE_CONFIG.yaml:** Defines artifact types that templates generate
- **EDITOR_PROFILE:** Provides personalization variables for templates
- **PROJECT_DISCOVERY:** Referenced in PROJECT_INSTRUCTIONS template

### With Workflows
- **All workflows:** Consume PROJECT_README for project context
- **Session management:** Uses PROJECT_INSTRUCTIONS for Claude.ai behavior
- **Configuration:** Uses PROJECT_CONFIG pattern for auto-save setup

## Troubleshooting

### Common Issues

#### **Generation Failures**
- **Missing variables:** Check TOOL_CREATE_PROJECT variable assignment
- **Template not found:** Verify template exists in _system/templates/
- **Permission errors:** Check write access to target directories

#### **Variable Substitution Errors**
- **Undefined variables:** Add missing variables to generation function
- **Special characters:** Check PROJECT_NAME_CLEAN processing
- **Path errors:** Verify DRIVE_URL generation logic

#### **Integration Issues**
- **Claude.ai setup:** Verify PROJECT_INSTRUCTIONS format
- **Auto-save config:** Check template generates valid PROJECT_CONFIG
- **Profile detection:** Test with multiple EDITOR_PROFILEs

### Validation Commands
```javascript
// Test template generation
testCreateProject()

// Check template integrity
validateTemplateVariables()

// Verify output format  
validateGeneratedArtifacts()
```
