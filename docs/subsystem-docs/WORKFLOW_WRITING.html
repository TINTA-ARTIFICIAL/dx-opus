01 — Propósito

Qué hace el subsistema Writing

Writing es el subsistema que transforma el conocimiento validado producido por Research en texto publicable. Su función es producir prosa con voz editorial —no resúmenes de fuentes— a partir del material que el editor ha investigado y aprobado.

La diferencia fundamental entre Research y Writing no es de contenido sino de rol. En Research, el sistema actúa como investigador: su objetivo es ser exhaustivo y fiel a las fuentes. En Writing, actúa como escritor: su objetivo es construir narrativa, mantener la voz del editor y producir texto que merezca ser leído. Esa transición de rol es lo que hace que un libro de no-ficción sea un libro y no un informe.

El sistema nunca escribe sin dirección editorial. Cada unidad —capítulo, sección o post— se produce para ser revisada y aprobada antes de continuar. El editor no delega la autoría: supervisa la ejecución de un plan que él mismo ha diseñado.

La bifurcación Book / Post

La decisión de rama ocurre al inicio de cada proyecto de escritura, antes de invocar cualquier prompt. Dos criterios la determinan: el formato de output que el editor quiere producir y el tipo de investigación disponible.

Rama Book
LIBRO
Extensión: 20.000–38.000 palabras
Estructura: 10–12 capítulos + especiales
Input principal: RESEARCH_REPORT(s)
Producción: 86–207 horas
Destino: Activation (campaña de contenido)
Proceso largo y secuencial. Cada capítulo conoce los anteriores. El estilo se fija en la Fase 2 y se mantiene constante hasta el cierre.
Rama Post
POST
Extensión: 500–5.000 palabras
Estructura: 1 unidad (artículo, post largo o hilo)
Input principal: RESEARCH_DEEP_DIVE o POST_SEED
Producción: 2–6 horas
Destino: Publicación directa
Proceso ágil de 3 fases. Puede iniciarse desde Research o desde un Narrative Seed del workflow de Activation.

Cuándo usar este workflow

  • 01Tienes un Research Report o Research Deep Dive aprobado (GREEN o YELLOW aceptado) y quieres convertirlo en texto publicable.
  • 02Tienes un POST_SEED producido por el workflow de Activation y quieres desarrollarlo en un post o artículo.
  • 03Quieres retomar un libro en curso: el sistema puede incorporarse en cualquier fase si existen capítulos previos.
  • 04Quieres evaluar el estilo de un texto ya escrito antes de decidir si lo publicas o lo incorporas a un libro en curso.
02 — Conceptos clave

El modelo conceptual

Writing opera sobre un conjunto de conceptos específicos que regulan cómo se construye la voz editorial, cómo se mantiene la coherencia a lo largo de un libro y cómo se garantiza la calidad antes de publicar.

El Perfil Editorial

El Perfil Editorial es el modelo de voz del editor aplicado a cada texto que produce el sistema. Captura cómo escribe ese editor: qué estructuras prefiere, qué registro usa, qué densidad de prosa le es propia, con qué tipo de ejemplos argumenta, qué evita.

En Writing, el Perfil Editorial tiene un rol diferente al que tiene en Research. En Research actúa como orientador del foco de investigación. En Writing actúa como regulador estilístico activo: cada texto producido se confronta con el perfil para verificar que la voz resultante es la del editor, no la del modelo.

En la práctica
Cómo opera el perfil
El perfil se carga como input en todos los prompts de escritura. No es un checklist que el sistema consulta al final — es parte de la instrucción que guía cada párrafo. Las correcciones manuales que el editor hace sobre los textos producidos también son señales de voz que pueden incorporarse al perfil.
Múltiples perfiles
Un perfil por proyecto
El editor puede tener perfiles distintos para proyectos distintos — una voz para libros académicos, otra para divulgación, otra para posts en redes sociales. Cada proyecto tiene un perfil activo asignado que el sistema usa durante toda la producción.

El Style Guide del libro

El Style Guide no existe antes de empezar a escribir — se produce durante la Fase 2 de la Rama Book, a partir del capítulo de muestra. Es la referencia canónica de estilo para ese libro concreto: no para libros en general, ni para el editor en general, sino para ese proyecto específico.

Una vez fijado el Style Guide, todos los capítulos posteriores lo reciben como input junto con el Perfil Editorial. Los dos documentos cumplen funciones distintas y complementarias: el Perfil Editorial captura la voz del editor como persona; el Style Guide captura las decisiones de estilo tomadas para ese libro — nivel de formalidad, densidad de citas, longitud de párrafos, uso de ejemplos concretos, tono de los apartados de análisis.

El capítulo de muestra

Antes de escribir los capítulos centrales del libro, el sistema escribe un capítulo de prueba — no necesariamente el primero del índice, sino el más representativo del tono que tendrá el libro. El propósito es doble: detectar desajustes de voz antes de comprometer muchas horas de producción, y producir el Style Guide que guiará el resto.

El capítulo de muestra no se descarta si sale bien. Se convierte en el primer capítulo validado del libro. Pero si el editor necesita correcciones sustanciales de estilo, es mucho mejor descubrirlo en el capítulo 1 que en el capítulo 8.

Escritura secuencial con coherencia acumulativa

Los capítulos de un libro no se escriben en paralelo. El sistema produce un capítulo, el editor lo revisa y aprueba, y solo entonces se avanza al siguiente. Esta secuencialidad no es una limitación operativa — es una decisión de diseño que garantiza dos cosas: que el editor mantiene el control editorial en cada unidad, y que cada capítulo nuevo conoce los anteriores y puede evitar repeticiones o contradicciones.

Los capítulos aprobados se convierten en fuente canónica para los capítulos siguientes. El sistema los lee antes de escribir el nuevo para mantener la coherencia narrativa, las referencias cruzadas y la distribución de contenido a lo largo del libro.

El Q&A de ideas

El Q&A de ideas es un mecanismo disponible en la Rama Post que invierte la dirección habitual de la interacción. En lugar de que el editor le diga al sistema qué escribir, el sistema hace preguntas secuenciales al editor sobre el tema, el argumento o el ángulo del post que va a producir.

Las respuestas del editor no se reescriben ni se parafrasean: se incorporan al texto tal cual. Lo que el editor dice en el Q&A es el material más valioso del resultado — su perspectiva genuina, sus ejemplos propios, su forma de ver el tema que ninguna fuente externa puede replicar. El Q&A produce además un POST_SEED que concentra ese material en un briefing estructurado listo para la escritura.

Los evaluadores de Writing

Writing invoca tres evaluadores externos al cierre de cada producción. Ninguno de los tres es propiedad del subsistema Writing — los desarrollan y mantienen Editorial Profile y Evaluation. Writing los invoca como paso obligatorio antes de considerar cerrado un texto.

EVALUATE_BOOK_STYLE
Owner: Editorial Profile
Evalúa si el texto es fiel al Perfil Editorial del editor. Detecta desviaciones de voz, tono y registro. Aplica en Rama Book (Fase 5) y puede aplicarse a cualquier texto.
EVALUATE_BOOK_CONTENT
Owner: Evaluation
Evalúa coherencia argumental, solidez de razonamientos, uso correcto de fuentes y ausencia de problemas típicos de escritura asistida. Aplica en Rama Book (Fase 5).
EVALUATE_POST
Owner: Evaluation
Evalúa voz, estructura, registro y calidad editorial del post. Aplica en Rama Post (Fase 3). Produce GREEN / YELLOW / RED con recomendaciones específicas.
03 — Referencia operativa

Diagrama del flujo

El flujo se bifurca al inicio. Selecciona la rama según el formato de output. Los paneles son expandibles — usa este diagrama como referencia durante la ejecución.

Inputs del sistema
  • EDITOR_PROFILE — perfil editorial activo del editor (obligatorio)
  • RESEARCH_REPORT(s) — para Rama Book (uno o varios según el proyecto)
  • RESEARCH_DEEP_DIVE — para Rama Post desde Research
  • POST_SEED / POST_BRIEFING — para Rama Post desde Activation
  • BOOK_BRIEF — orientador opcional desde Activation
ENTRADA DECISIÓN DE RAMA — BOOK O POST 5 min ▾
🔀
Criterio de decisión
→ RAMA BOOK si el output es un libro (10–12 caps, 20k–38k palabras) con RESEARCH_REPORT como input principal
→ RAMA POST si el output es un artículo, post o hilo con RESEARCH_DEEP_DIVE o POST_SEED como input principal

La decisión es irreversible dentro de un proyecto. Una vez elegida la rama, todos los prompts del flujo corresponden a esa rama.

RAMA BOOK — ESCRITURA DE LIBRO
FASE 0 PREPARACIÓN Variable ▾
👤
Actor: Editor
Reúne RESEARCH_REPORT(s), EDITOR_PROFILE y fuentes originales. Si el libro retoma un proceso anterior, incorpora capítulos ya escritos. Verifica que el Research haya sido aprobado como GREEN (o YELLOW aceptado).
FASE 1 CREACIÓN DEL ÍNDICE 2–4 h ▸
📑
PROMPT_CREATE_BOOK_INDEX v1.0
Propone el índice completo del libro: títulos de capítulos, arco narrativo, distribución de contenido. El editor ajusta y aprueba la estructura antes de escribir una sola palabra.
📤
Output
BOOK_INDEX — referencia estructural para todas las fases siguientes
✅ CHECKPOINT 1 — Editor aprueba el índice antes de continuar
FASE 2 CAPÍTULO DE MUESTRA Y ESTILO 6–12 h ▸
🖊️
PROMPT_WRITE_SAMPLE_CHAPTER v1.0
Escribe el capítulo más representativo del libro como prueba de estilo. El editor revisa y corrige. A partir del capítulo aprobado se produce el STYLE_GUIDE_LIBRO.
📤
Output
SAMPLE_CHAPTER_FINAL + STYLE_GUIDE_LIBRO — referencia canónica de estilo para el resto del libro
✅ CHECKPOINT 2 — Editor valida capítulo y style guide antes de producción en serie
FASE 3 ESCRITURA DE CAPÍTULOS (SECUENCIAL) 6–10 h / cap. ▸
✍️
PROMPT_WRITE_CHAPTER v1.3 — por capítulo
Un capítulo a la vez. Cada ejecución lee todos los capítulos previos aprobados para mantener coherencia narrativa y evitar repeticiones. Jerarquía de versiones: FINAL_EDITED > FINAL > v2.0 > v1.0.
🔁
Inputs por capítulo N
BOOK_INDEX + STYLE_GUIDE_LIBRO + EDITOR_PROFILE + fuentes del capítulo + CHAPTER_01...(N-1)_FINAL
⚑ CHECKPOINT N — Editor aprueba cada capítulo antes de avanzar al siguiente
FASE 4 CAPÍTULOS ESPECIALES 4–8 h ▸
📝
PROMPT_WRITE_INTRODUCTION v1.0
Escribe la introducción del libro una vez que todos los capítulos centrales están aprobados. La introducción anuncia sin revelar; presenta el argumento central sin anticipar las conclusiones.
🖋️
PROMPT_WRITE_PROLOGUE v1.0
El prólogo es el espacio más personal del libro. El editor puede escribirlo directamente o con asistencia del sistema. A diferencia de los capítulos, el prólogo puede diferir conscientemente del STYLE_GUIDE: es la voz del editor sin mediaciones.
FASE 5 CONSOLIDACIÓN Y CIERRE 8–14 h ▸
⏱️
PROMPT_CREATE_TIMELINE v1.0 SHARED
Cronología de hechos, eventos y periodos cubiertos por el libro. Input: todos los capítulos + Research Reports.
👥
PROMPT_CREATE_CAST v1.0 SHARED
Elenco de personajes, instituciones y entidades relevantes con perfiles estructurados. 15–30 entradas típico.
📚
PROMPT_CONSOLIDATE_REFERENCES v1.1
Elimina duplicados, normaliza formato (IEEE/APA/Chicago), sustituye referencias a Research Reports por fuentes originales, verifica que toda cita tiene referencia y toda referencia está citada.
📊
EVALUATE_BOOK_STYLE + EVALUATE_BOOK_CONTENT
Evaluación obligatoria antes de cerrar. EVALUATE_BOOK_STYLE (owner: Editorial Profile) verifica voz y coherencia estilística. EVALUATE_BOOK_CONTENT (owner: Evaluation) verifica coherencia argumental y solidez de fuentes.
📋
PROMPT_CREATE_BOOK_SHEET v1.1
Ficha técnica del libro. Incluye declaración obligatoria de producción asistida por IA (política de transparencia).

RAMA POST — ESCRITURA DE POST / ARTÍCULO
FASE 0 PREPARACIÓN 15–30 min ▾
👤
Actor: Editor
Define el punto de entrada: ¿viene de Research (RESEARCH_DEEP_DIVE) o de Activation (POST_SEED / POST_BRIEFING)? Define formato objetivo: post estándar, artículo largo o hilo.
FASE 1 PLANIFICACIÓN DEL POST 30–90 min ▸
💬
PROMPT_QA_IDEAS (opcional)
Diálogo estructurado donde el sistema pregunta al editor sobre el ángulo, el argumento y los ejemplos que quiere usar. Las respuestas se incorporan al texto tal cual. Produce material citable + POST_SEED.
📐
PROMPT_POST_ANGLES + PROMPT_PLAN_POST v1.0
Explora ángulos narrativos posibles y propone la estructura del post: hook de apertura, secciones, puntos clave, cierre. El editor ajusta y aprueba el plan.
📤
Output
POST_PLAN — estructura aprobada + POST_SEED (si hay Q&A)
⚑ CHECKPOINT — Editor aprueba estructura antes de escribir
FASE 2 ESCRITURA 1–3 h ▸
✍️
PROMPT_WRITE_POST v2.0 SHARED
Escribe el post desde POST_SEED + POST_PLAN + EDITOR_PROFILE. Soporta tres formatos: post_estándar · post_largo · hilo. Si el borrador supera la extensión del formato, se invoca PROMPT_SPLIT_POST para dividirlo en dos piezas autónomas.
✂️
PROMPT_SPLIT_POST v1.0 (si aplica)
Divide un post que excede el formato en dos piezas. Produce: post 1 ajustado para quedar autónomo + POST_BRIEFING del post 2. Invocable en cualquier momento del proceso.
📤
Output
POST_DRAFT → revisión editorial → POST_FINAL
FASE 3 EVALUACIÓN Y PUBLICACIÓN 30–60 min ▸
📊
EVALUATE_POST v1.0 OWNER: EVALUATION
Evalúa voz, estructura, registro y calidad editorial. Produce GREEN / YELLOW / RED con recomendaciones específicas. El editor decide si publicar o revisar.
✅ POST APROBADO → Publicación directa
Output final — Rama Post
└── POST_FINAL (post_estándar / post_largo / hilo)
→ Publicación directa en plataforma del editor
Prompts compartidos
PROMPT_WRITE_POST, PROMPT_CREATE_TIMELINE y PROMPT_CREATE_CAST son owned por Writing pero también invocados por Activation. Si se modifica alguno de ellos, Activation puede verse afectado.
